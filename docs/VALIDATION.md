# Перевірка першої версії

Це історія перевірок. Відомості про пароль і сесії нижче стосуються початкової версії: за подальшою вказівкою власника їх прибрано. Актуальний доступ — без входу; див. останній розділ.

Дата: 2026-09-09. Node.js 24.19.0, FFmpeg 6.1.1 у середовищі розробки.

Пройдено 13 перевірок ядра та інтеграційну перевірку повного дня (14 тестів):

- спадкові параметри першого каналу не активують доступ або публікації;
- київські дати, літній/зимовий зсув, пауза перед повтором, два різні товари та fallback за одного;
- збереження каталогу й резервів, відновлення перерваної черги без автоматичного повтору платного запиту;
- блокування Drive поза дозволеною папкою до запису;
- відсутність прихованого повтору/заміни провайдера при помилці та повторне використання озвучки з кешу;
- відхилення неповних відповідей і близьких текстових повторів;
- продовження лише незавершених матеріалів;
- вхід, підробка сесії, CSRF, закриті API, коректні й некоректні Range-запити;
- реальний повний пакет дня: два MP4, картинки, SRT, обкладинки, ZIP; ffprobe підтвердив 1080×1920, yuv420p, AAC 48 kHz stereo; карусель — 1080×1350;
- сторіз-поширення посилаються на актуальні результати батьківського матеріалу.
- вечірній імпорт Drive виконується до вибору нових товарів; опублікований підпис зберігає ціну на момент ручної позначки.
- заміна чернетки атомарна; помилка не стирає попередній день, а опублікований день замінювати заборонено.

Платні генерації OpenAI/ElevenLabs та живий імпорт/запис у Google Drive не запускалися: ключі Railway не надавалися середовищу розробки. Тести провайдерів використовують контрольовані відповіді; тестова озвучка — короткий синтетичний сигнал, а не оцінка якості голосу.

Спроба відкрити локальний застосунок у доступному Cloud Browser завершилася `ERR_BLOCKED_BY_CLIENT` для localhost. Візуальне й інтерактивне тестування в цьому браузері не завершене. HTTP-маршрути, формати файлів і синтаксис JavaScript перевірено окремо.

Railway не перемикали; реальний deploy, доступ до ключів і якість першої української озвучки перевіряються після налаштування другого сервісу. Файл Docker використовує Node 24 / Debian Bookworm і системний FFmpeg; Docker-збірка тут не виконувалась.

## Перевірка виправлення запуску на Railway — 2026-09-09

Після перемикання репозиторію користувачем GitHub показав `Deployment failed` для `YouTubeStories - tiktok-chanel` на коміті `bebd986e3404ed4fbd0041d4b20f15b14df788aa`. Статус GitHub не містив логів із причиною збою.

Локально відтворено зупинку процесу без `MARYLEE_ADMIN_PASSWORD`, без підключеного Volume та при відсутності `MARYLEE_DATA_DIR` навіть за наявності Volume. Виправлено останній випадок: шлях береться з автоматичної змінної Railway. Якщо бракує пароля й Volume, повідомлення тепер містить обидві причини одразу. Обов’язковий пароль і перевірка постійного сховища залишаються чинними.

Після виправлення пройдено **15 тестів** командою `node --test test/core.test.js test/startup.test.js`: 14 перевірок ядра та новий тест фактичного запуску `node src/server.js` в окремому процесі з production-конфігурацією і тимчасовою папкою, яка імітує Volume. Перевірено `/healthz`, закритий API до входу, захищену cookie, запис каталогу саме в папку Volume та збереження товару після перезапуску процесу. Синтаксис JavaScript перевірено окремо.

Це перевірка процесу Node.js, а не Docker-збірки або живого монтування Railway. Реальні логи й успішний deploy потрібно підтвердити через доступ до Railway. Платні API та Drive у цій перевірці не викликаються.

## Запуск і вилучення авторизації — 2026-09-09

Початковий запуск на Railway підтверджений: deployment `3706ab58-6b7b-4709-9e66-db8773fa7675` отримав `SUCCESS`, `/healthz` пройшов перевірку, окремий Volume змонтовано в `/data`.

За подальшою прямою вказівкою власника прибрано форму входу, кнопку виходу, сесії та перевірку `MARYLEE_ADMIN_PASSWORD`. Усі функції доступні відвідувачам за посиланням. Перевірка походження запитів, ліміти генерації та ізоляція Drive діють і надалі; вони не замінюють авторизацію.

Пройдено 15 регресійних тестів ядра та запуску для доступу без пароля: відкритий каталог і медіа, запис товару, збереження після перезапуску, відсутність передачі серверних секретів, блокування стороннього Origin та запитів без службового заголовка. Синтаксис JavaScript та відповідність посилань інтерфейсу до HTML-елементів перевірено. Живі платні генерації цим тестуванням не виконуються.

## Повнота відповіді ШІ — 2026-09-09

Deployment `4a5e6ddd-de0a-491e-afd0-60e170539ead` з вилученням авторизації отримав `SUCCESS`. Живий застосунок відкрився без входу; каталог містив два додані користувачем товари, а план на 2026-09-10 — вісім чернеток із помилкою неповної відповіді ШІ.

Попередня схема Structured Outputs дозволяла масив довільної довжини: навіть коректний JSON міг не містити всі слоти. Відповідь тепер має обов’язкове поле для кожного запитаного слота, фіксований `slotId` і кількість сцен, ключових слів, хештегів та відповідей опитування відповідно до формату. У запиті окремо пояснено тексти для сторіз-поширень. Валідація та ручний повтор збережені; прихованих додаткових платних запитів немає.

Команда `node --test test/ai.test.js test/core.test.js test/startup.test.js` пройшла 24 перевірки. Нові тести проходять через реальний клас AI та чергу Worker з контрольованою відповіддю провайдера: вісім матеріалів двох товарів зберігаються у правильному порядку, дев’ятий необов’язковий слот та повтор одного опитування працюють окремо. Неповна відповідь, невідомий або переплутаний слот, null-матеріал, обрив через ліміт токенів та відмова провайдера не змінюють попередній план і не викликають платних повторів. Рендер у цих нових тестах підмінений; перевірку реального FFmpeg описано вище.
