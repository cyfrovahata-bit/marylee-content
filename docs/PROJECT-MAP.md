## Як проходить день

Каталог → «Згенерувати дні» → усі ще не заплановані товари, по два з завтра (5 = 2+2+1) → товарні матеріали через текстовий API та FFmpeg → окремі JSON-завдання Reel/poll у Sheets/Drive → GPT повертає ZIP → API опису, озвучка перевірених реплік і монтаж → ручна публікація. Останній один товар отримує карусель і Reel з різними описами.

Розклад за Києвом: 09:00 порада й одразу поширення; 12:00 опитування; 14:00 карусель A; 15:30 деталь A; 18:30 знайомство з B; 19:30 Reel B й одразу поширення. Разом 3 публікації та 5 сторіз. 21:30 — необов’язкова сторіз. Автопланування нових товарів за бажанням — 22:30; після очищення вимкнене.

- Тема поради не передається продажним слотам. Опис Reel разом із короткими фактами до 250 символів, далі 15–20 ключових слів і п’ять малих хештегів. Сторіз — до 90 символів.
- Тексти: `MARYLEE_TEXT_MODEL`, стандартно GPT-4.1. Малювання через API вимкнено на рівні HTTP, Worker та AI.image; старі змінні imageModel/imageReserve не запускають малювання.
- Голос порад: `MARYLEE_TTS_ENGINE=openai`, `MARYLEE_OPENAI_VOICE=marin`. Старі `TTS_ENGINE` і `TTS_OPENAI_VOICE` не визначають голос Marylee.
- Продажний Reel: чотири короткі написи, приблизно 15 секунд, тиха звукова доріжка. Тільки оригінали товару.
- Нові плани: externalImages=true у morning і poll. Reel очікує 4 окремі фото та перевірені репліки; poll — власний diptych. Шаблони загальні, змінні у JSON. Старий ручний маршрут з одним diptych збережено лише для сумісності. Текстовий API не замінює approvedStory; після збою підтвердження Sheets імпорт не повторюється.
- Без зображення ранковий Reel і залежні матеріали мають статус awaiting-image; товарні слоти завершуються. waiting-parent означає очікування готового Reel для поширення. Це не помилка провайдера.
- У кожного матеріалу є goal (призначення), а в редакторі товарних дописів видно fullCaption з характеристиками. Карусель додає всі заповнені поля каталогу; короткий Reel — ціну, артикул і розміри. Сторіз показує решту даних як довідку.
- Добові межі: 24 текстові запити й 10 000 символів голосу; ілюстрації через API не створюються; типовий резерв $5. Не збільшувати заради перевірок.
- «Перегенерувати день» оновлює неопубліковані товари та створює нові завдання зображень. Репости — локальні дії, без зайвих API-запитів. Для стандартного дня спершу два текстові запити на товари; описи поради й poll створюються після імпорту їх ZIP. «Підготувати матеріали» використовує наявні тексти та кеш. Для дрібних виправлень редагувати вручну.
- Схема ШІ залишає неактуальні поля порожніми (зокрема imagePrompt товарів і pollQuestion звичайних дописів), щоб не витрачати токени на них. Запитання опитування обирається з коротких завершених варіантів.

## API і збереження

- `GET /api/state?date=YYYY-MM-DD` — каталог, план, завдання, резерви, ознаки налаштування без ключів.
- `POST /api/plans/batch` — планування незапланованого каталогу із завтра, ідемпотентне.
- `POST /api/queue/sync`, `GET /api/queue/prompt` — перевірка Drive та актуальний промпт щогодини.
- `POST /api/content/reset` `{confirm:"MARYLEE"}`, `POST /api/content/restore` `{id}` — очищення та відновлення до нового завантаження; integration/settings/usage збережено.
- Таблиця Queue: `1G55IRRugATfv_l1gqDlPOrCcqVJ2YSj3ryC25CIKsSw`, Marylee root `1i0azNN9VkiD7hSsYTjkGPhQfl2elQHeO`. Протокол/колонки/ліміти — у `docs/GPT-QUEUE.md`. Не чіпати стару YouTube таблицю. При зміні шаблонів збільшити templateVersion у `ContentQueue.setup`, щоб оновити їхні копії на Drive.
- `POST /api/plans/:date/prepare` — `{mode:"render"|"text"|"all", itemId?:"evening"}`. Без itemId працює партіями для всього неопублікованого дня.
- `PUT /api/plans/:date/items/:id` — ручні правки.
- `POST /api/plans/:date/items/morning/illustration?name=looks.png` — JPG/PNG/WebP як тіло запиту, збереження та автоматична черга монтажу. Повторно перевіряє статус і revision після завантаження.
- `POST /api/image` завжди повертає 410 без звернення до Images API.
- `POST /api/jobs/:id/retry` — продовження зі збереженими контрольними точками.
- `GET /api/plans/:date/export` — ZIP дня. `GET /media/:id` — результат; відео підтримує Range.
- Записи: `/data/marylee.sqlite`. Оригінали та результати: `/data/media`; кеш голосу: `/data/cache`; тимчасові файли: `/data/work`.
- Для API-змін потрібен `X-Marylee: 1`; збережено перевірку Origin. Входу через пароль немає за рішенням власника.
- Повна перегенерація не редагує вже опубліковані записи. Поширення неопублікованого Reel підхоплюють нові файли батьківського матеріалу.

## Мінімальна перевірка

- Сценарії/генерація: `node --test test/ai.test.js test/content.test.js`
- Сервер/збереження/налаштування: `node --test test/core.test.js test/startup.test.js`
- Монтаж: `node --test test/media.test.js` — справжні FFmpeg, JPEG, MP4, SRT, ZIP; перевіряє підготовку товарів без ілюстрації, реальне завантаження та продовження, нуль запитів малювання, тишу в продажному відео й повтор після помилки голосу.
- Синтаксис JS: `node scripts/check.js`
- Черга/пакети/очищення/ZIP/перевірений сценарій: `node --test test/queue.test.js` (справжній FFmpeg для імпортованих кадрів).

Не запускати всі перевірки повторно без конкретної причини. Детальний журнал — `docs/VALIDATION.md`.
