# Marylee: read this first

Standalone Ukrainian clothing content app. Repository: `cyfrovahata-bit/marylee-content`, branch `main`.

## Critical boundaries

- Do not modify `tiktok-chanel`, its branch/deployment, or the `TikTok Channel` Drive folder.
- Only the repurposed Railway **YouTubeStories** service belongs to Marylee. IDs and code paths are in `docs/PROJECT-MAP.md`.
- Manual social publication only. No password login (owner explicitly removed it).
- Sales/product Reels always have **no narration**, regardless of settings. Style tips use the Marylee voice profile.
- Never use AI imagery as a photo of the product being sold. Never expose supplier/drop prices or contacts in captions.
- Respect the configured daily budget and generation caps. Preserve originals, completed batches and paid-generation checkpoints.

## Work efficiently

1. Read `docs/PROJECT-MAP.md` once. Inspect only the files relevant to the request; do not rediscover this repository or other accounts.
2. Fetch the current `main` SHA before publishing. Use its tree as the base; update only changed files. This checkout may have no local HEAD, so a raw local git diff is not the remote baseline.
3. Reuse connected tools and known Railway IDs. Do not list every project, variable or folder. Never print secrets or full connector responses.
4. Run the smallest meaningful checks for the change. Only montage changes need the real FFmpeg test. Stop when the concrete risk is covered.
5. For a whole day, use its batch operation; do not generate eight posts one by one. For a correction, target only that item. Reuse completed image and voice work after failures.
6. Do not reload or reopen the same data unless it changed or a concrete question remains. Reuse tool documentation already read within the session.
7. Update the map only when architecture or operations change. Keep progress messages short; report actual completion and any remaining issue.

This code is stored in GitHub. Do not duplicate repository files in another artifact store.
